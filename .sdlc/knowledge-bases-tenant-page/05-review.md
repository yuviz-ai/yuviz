# Code review
VERDICT: AMBER

1. [minor] Detail page renders every write control to read-only roles — no `canManage` gate — `admin-ui/app/knowledge-bases/[tenantSlug]/[kbId]/page.tsx:227` (also :198 Upload, :239 Attach picker, :264 Detach) — fails when: a tenant `viewer` (who the design deliberately gives 200 on this page, AC14) opens a KB and clicks Delete/Detach/Upload → 403 error banner on a button that should never have been shown. The list page correctly gates "+ Add source" on `getCurrentUser()` (`page.tsx:76-81`); the detail page drops that check entirely (lesson 22, design "Page data flow"). — fix: fetch `getCurrentUser()` here too and hide upload/delete/attach/detach unless role is `superadmin`/`admin`.

2. [minor] Blanket `.catch(() => setNotFound(true))` reports every load failure as "not found" — `admin-ui/app/knowledge-bases/[tenantSlug]/[kbId]/page.tsx:87` — fails when: Knowledge Service is down or `listKnowledgeBases` 500s → the page says "Knowledge base not found.", so an operator can conclude the KB was deleted and re-create it. The design asked for a 404-style state only when the KB is *absent*, with each section error-handled independently. — fix: set `notFound` only on the `!t` / `!found` branches and render the caught error as a page-level error with a retry.

3. [minor] A failed upload after a successful KB create strands an empty KB and makes retry impossible — `admin-ui/components/AddSourceModal.tsx:101-107` — fails when: `createKnowledgeBase` succeeds and `uploadDocument` then fails (unsupported content type at the API, storage error, network drop) → the KB row is persisted, `target` is still `"new"` with the same slug, so pressing Upload again returns the API's duplicate-slug error and the user can never complete the flow without inventing a new slug; an empty KB is left behind each time. — fix: store the created KB id in state and reuse it on retry instead of re-creating.

4. [minor] `agentsError` is shared by two unrelated fetches, so a successful refresh erases the other one's error — `admin-ui/app/knowledge-bases/[tenantSlug]/[kbId]/page.tsx:85` vs `:40-48` — fails when: `listAgents(tenantSlug)` fails (403 for a role with no Config agent surface, or a 500) → the banner appears, but the next attach/detach calls `refreshAgents()`, which succeeds and sets `agentsError` to null; the "+ Attach agent…" picker is then absent with no explanation at all. — fix: give the tenant-agent picker its own error state.

Not findings, checked and clean: the new `GET /knowledge-bases/{kb_id}/agents` matches the design's stated behaviour in order, uses `is_platform_scoped` rather than a role test (lesson 24), returns a 404 detail byte-identical to the existing handler's (lesson 2), and maps the malformed-uuid `asyncpg.DataError` to the same 404; `list_for_kb` carries both `deleted_at` filters; `test_cross_tenant_admin_gets_same_404_as_unknown_id` is the case the query's joins cannot reach, so deleting the handler predicate does turn it red (lesson 12); the list page uses `allSettled` per tenant/KB rather than a bundling `Promise.all` (lesson 21) and gates its write control on `/auth/me` (lesson 27/35).
