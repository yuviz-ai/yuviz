# Security review: .sdlc/outbound-campaign-calling/05-phase6-design.md (round 2)
VERDICT: GREEN

## Findings
None open. R1 finding 1 (critical, a tenant-scoped superadmin could reach the platform capacity routes) is **fixed**: the design changes, the server gate, the UI gate and the test matrix all match the R1 fix.

## Verified controls
- **Platform scope gate (R1 #1).** `require_platform_operator` checks `user.role == "superadmin" and is_platform_scoped(user)`. `is_platform_scoped` is `user.tenant_id is None` (`services/config/deps.py:64-66`), the canonical predicate from lesson 24. The gate depends on `get_current_user` (`deps.py:54-61`), which rebuilds `CurrentUser` from the fresh `users` row via `_row_to_effective_user` (`deps.py:139-147`). So `tenant_id` comes from the DB, not the JWT. A tenant-scoped superadmin gets 403 on all 7 routes.
- **Re-tenanting lag.** If a platform superadmin is moved into a tenant or demoted, Campaigns keeps the old scope for up to the ~60s console memo. Config's `forget_user` only clears Config's own process. This is the documented lesson-27 window, the design names `get_current_user` as what it relies on, and it is not a new exposure.
- **Service accounts.** They are created only as `role="viewer"` with a NULL tenant (`scripts/create_service_account.py:28`), so they fail the role half of the gate and get 403. No superadmin service account path exists.
- **Gate placement and awaiting.** The gate is a router-level `APIRouter(dependencies=[...])` entry, so FastAPI awaits it (lesson 38). In `solve_dependencies`, sub-dependencies resolve before path, query and body params are validated. Path params are `str`. So a non-operator sending a schema-invalid but well-formed body gets 403, not 400. The design correctly calls out the one exception: unparseable JSON gets 400 for every caller, and that response varies with no tenant or existence signal.
- **Per-caller invariance (lesson 2).** The 403 text is constant. The test plan asserts identical status and body for own-id, B-id and a random UUID with each principal held fixed. That is per-caller invariance, not a cross-principal comparison.
- **Test matrix.** `test_capacity_routes.py` covers admin-A, viewer-A, the service account (viewer, NULL tenant) and the tenant-scoped superadmin (superadmin, tenant A), each with schema-valid bodies so the gate is what gets tested. It snapshots limits, CPS, tenants and the audit count before and after.
- **UI gate.** `useConnectionAccess` adds `isPlatformOperator: role === "superadmin" && tenantId === null`, with `tenant_id` taken from `/auth/me`. `/auth/me` returns the fresh DB row (`services/config/routers/auth.py:216-223`, `User.tenant_id: string | null` at `admin-ui/lib/api.ts:1225`). `CapacityCard` mounts only when `checked && isPlatformOperator`, and the card owns its fetches, so no `/capacity` request is made otherwise. A missing or undefined `tenant_id` fails closed (`undefined !== null`). The server gate remains the actual control.
- **Lesson 9.** The gate is defined locally in `routers/capacity.py`, so no consumer of `services/config/deps.py` is widened.
- **Capacity inputs.** The CPS `scope` path param is checked by `_CPS_SCOPE.fullmatch` before any SQL (`services/campaigns/capacity.py:123-126`). All setters are parameterized. A non-UUID tenant id gets 404 before `set_tenant_cap`. The schemas are strict and require every key.
- **Atomic writes.** Each write does singleton `FOR UPDATE`, then reads the old value, calls the setter and runs `write_audit` on one connection. A `LimitError` rolls back both the row change and the audit row. `admit()` uses plain reads, so the lock never blocks dialing.
- **Caller-ID route.** It sits on `tenant_scoped_router`, which carries `bind_path_tenant` and `require_path_tenant_access` (`services/campaigns/routers/campaigns.py:24-27`). The query also has an explicit `pn.tenant_id = $1` and `tc.tenant_id = pn.tenant_id` (lessons 36 and 48). `test_cross_tenant_admin.py` covers tenant-B admin → 403.
- **Attempts.** `list_attempts` authorizes through `_campaign_for` (one 404 for a missing campaign and for another tenant's). `list_for_campaign` keeps `campaign_id = $1 AND tenant_id = $2` (`services/campaigns/attempts.py:73`). The `calls` join keys on `session_id` plus `k.tenant_id = t.slug` and reads only `disposition`, gated on `answered_at`. The raw callee is popped into `_mask_callee` inside the function. Values with 4 or fewer digits are fully masked.
- **Error echo.** The new `RequestValidationError` handler drops pydantic `input` and `ctx`. `LimitError` messages are fixed strings and go out through the existing `ValueError` → 400 handler (`services/campaigns/app.py:73-75`).
- **Billing guard.** `_estimate` runs on its own `platform_conn` inside `wait_for` with `except Exception` → `None` plus one log line that carries no exception text. It cannot 500 readiness, Start or Resume, and a timeout releases its connection.
- **Audit PII.** Capacity audit rows carry only limits and caps, never a callee. `/audit-log` is superadmin-only and scoped by `tenant_id` for tenant-scoped callers. Residual R1 note, not a finding: the design still does not say whether tenant-cap rows are stamped with the tenant. At most this would let tenant A's own scoped superadmin see tenant A's cap, which `progress.effective_limit` already reveals to that tenant.
- **Network.** There is no new listener or bind. The routes ride the existing JWT-authenticated Campaigns `:8400` app.
