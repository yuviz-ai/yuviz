# Code review
VERDICT: AMBER

1. [minor] FreeSWITCH and Kamailio disagree on the allowed `max_call_s` range — `scripts/kamailio/kamailio.cfg.tpl:1220` (`^[1-9][0-9]{1,3}$`, 10–9999) vs `scripts/freeswitch/start_campaign_call.lua:50` (`^[1-9]%d%d?%d?$`, 1–9999) — fails when: billing is on and the `held` transition lowers `max_call_s` with `LEAST` to a value from 1 to 9 (a low-credit grant, which design A13 allows). FreeSWITCH accepts the intent, takes the claim and dials, then Kamailio's PSTN_EGRESS sends 403. The attempt is recorded as a rejected or declined hangup and the contact is redialed, when it should not have been dialed at all — fix: use the same bound in both places, and enforce it where the token is minted.
2. [minor] A 409 from Start or Resume replaces the whole readiness object with `{checks}` only — `admin-ui/app/(console)/campaigns/[id]/page.tsx:300` — fails when: a draft is showing a cost estimate, and Start returns 409 because the server found a blocking check (`routers/campaigns.py:194` returns `{"checks": [...]}` with no `estimate` or `ready`). The estimate line disappears from ReadinessPanel, and `ready` is now `undefined`, even though the cast claims the type is `CampaignReadiness` — fix: merge the checks into the existing readiness (`{...readiness, checks}`) instead of casting the body.
3. [minor] The usage error in CapacityCard is never cleared — `admin-ui/components/CapacityCard.tsx:170` (and `:177`) — fails when: one `/capacity/usage` poll fails (for example, Campaigns restarts). The red error stays on the card for good, next to fresh usage numbers from later successful polls, so the operator thinks usage is still broken — fix: call `setUsageError(null)` on success.
4. [minor] The "duplicate" result in the trigger script can never happen, and the header comment describes a log line that does not exist — `scripts/freeswitch/start_campaign_call.lua:63` and `:5`, `scripts/kamailio/kamailio.cfg.tpl:1587` — fails when: a second trigger arrives for a key. `GETDEL` on line 31 has already consumed the intent, so that trigger exits as `reject("no intent")` with a WARNING. It never reaches `SET NX`, and Campaigns never re-SETs an intent. Meanwhile `event_route[uac:reply]` logs only the status code, not `X-Campaign-Result`, so the "accepted/duplicate/rejected" outcome the comment promises does not appear anywhere in Kamailio's log — fix: drop the dead duplicate branch, or log `$hdr(X-Campaign-Result)` in `uac:reply` and fix the comment to match.
