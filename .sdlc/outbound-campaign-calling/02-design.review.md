# Review: 02-design.md (A13 billing focus)
VERDICT: AMBER

1. [blocking] `_billing_sync` writes `held→authorized` and `release_due→released` without saying the UPDATE is conditional on the state it read; `apply_outcome` can move the row to `settle_due` during the billing call, and a blind write would overwrite it and the settlement would never post (lesson 8) — Billing seam, `_billing_sync` bullets (lines 607, 609) — fix: specify both as `UPDATE ... WHERE id=$1 AND billing_state='held'|'release_due' RETURNING id`, and add a test that fires `ended` between the billing call and the write-back.
2. [minor] A refused or unavailable reserve unclaims with `next_attempt_at` unchanged, so every tick re-claims under the platform advisory lock and re-calls billing (2 s timeout each) while billing is down or credit is out — Dial admission step 3 / `unclaim` — fix: on unclaim set a campaign-level `not_before` (e.g. 30 s) or skip the campaign while its `wait_reason` is a billing reason.
3. [minor] The existing crash-recovery of `pending` attempts (criterion 16) is not excluded for `billing_state='reserving'`, so the 30 s `reserving` sweep and the pending-resend path can both act on one row, and a resend would go out with no hold — `worker._reconcile` / `_billing_sync` — fix: state that pending recovery only sends rows with `billing_state IN ('off','held')`.
4. [minor] A slow `reserve` that lands after the best-effort `release` creates an orphan hold, which keeps charging budget and credit until `expires_at` (deadline + 300 s) — contract item 3 / step 3 — fix: add a contract clause that `reserve` after `release` of the same key is refused, or repeat the release from the `_billing_sync` sweep.
5. [minor] Billing refusals `tenant_cap` and `budget_reached` reuse or extend the Campaigns cap labels, yet the WaitReason note says only `insufficient_credit` and `billing_unavailable` come from `unclaim`; billing `concurrency` is also indistinguishable from Campaigns' own `tenant_cap` in the UI — line 510 / Data CHECK — fix: list all four `unclaim` reasons and name the billing concurrency refusal separately (e.g. `billing_tenant_cap`).

Verified: no billing call on the media or per-turn path (only `sched_hangup` set from the intent); `max_outbound_concurrent_calls` is enforced only in `capacity.admit`; the settle path is idempotent (`settled` is terminal, re-settle returns the first `Settlement`, `spent_minor` moves in the same conditional transaction).
