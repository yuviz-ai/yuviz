# Security review: feature/outbound-campaign-calling (round 5, `git diff origin/redesign...HEAD`, focus on af99c22)
VERDICT: AMBER

0 critical, 0 high, 1 medium, 0 low. Prior findings: 1 fixed, 0 carried, 0 accepted.
- R4-1 [low] Telephony Redis user could write and delete `did:*`/`agent:*`: FIXED. The selector is now `(~agent:* ~did:* +get)`, the root has no key patterns, `services/config/cache.py` has been dropped from the inventory, and `test_redis_acl_matrix.py:150-155` checks against a real Redis 7 that SET, DEL and PUBLISH are refused.

## Findings
1. [medium] The Gateway now takes `tenant_slug`/`agent_slug` straight from the metadata frame whenever `direction == "outbound"`. That frame arrives over the unauthenticated audio WebSocket (`CallMetadata::direct_route`, `gateway/src/config/Config.cpp:336-339`; used at `gateway/src/core/Application.cpp:223-226`). Until this change, a client could only name a DID, and the Gateway resolved it through `did:*`. Now the client names the route itself.
   Attack: take any peer that can reach the Gateway WS. With the default bind that means any local process. In the split VM setup (`docs/telephony-vm-setup.md:222-228`, `GATEWAY_LISTEN_HOST=HOST_IP`) it means the VM network, kept out only by a firewall rule the doc recommends. That peer opens `/voice/<uuid>` and sends `{"direction":"outbound","tenant_slug":"<victim>","agent_slug":"<any>"}`. It then talks to any active agent of any tenant, including agents bound to no DID (drafts, internal, web-only), so their prompt and knowledge base can be pulled out by conversation. The LLM, STT and TTS spend lands on that tenant, and the call is recorded as outbound. Before this change the same peer could reach only DID-bound agents, by DID. Slugs are guessable (`sunrise-hospital/reception`).
   Fix: stop trusting the frame for the route. Have FS or Campaigns write a short-TTL `campaign:route:{call_uuid}` (or put the slugs into the intent's claim key) that the Gateway user can `+get`, and honour `direct_route` only when it matches. The other option is to HMAC the metadata with a secret shared by FS and the Gateway.

## Verified controls
- Gateway `direct_route` is gated on `direction == "outbound"`. `start_voice_ai.lua:36-46` emits `outbound` and the slugs only when `campaign_key` is set, and that variable is set only by `start_campaign_call.lua` originate vars, never from SIP. An inbound PSTN or SIP caller therefore cannot select an agent.
- Slug path end to end: the worker gets the slugs from `resolve_outbound_route` (`campaigns.py:207-215`), where `agent_ok` requires `a.tenant_id = t.id`, the agent active and not deleted. The worker refuses to dial unless both `caller_id_owned` and `agent_ok` hold (`worker.py:229`). Reconcile resends take the slugs from `list_open`, which joins `ag.tenant_id = a.tenant_id`, so a deleted agent yields NULL and `DialIntent` validation fails.
- Slug validation is identical at every hop: Python `_SLUG` (`dial_request.py:30`), Kamailio `^[a-z0-9][a-z0-9_-]{0,62}$` plus a byte-equal canonical rebuild (`kamailio.cfg.tpl:1530-1541`), and Lua quote-bounded `field()` patterns. The FS-side variable is `sip_token`-filtered. Nothing can inject a comma, brace or quote into the originate string or the metadata JSON.
- `campaign_event.lua`, now a global hook: it returns immediately for any channel without `variable_campaign_key`, so inbound calls of every tenant emit nothing. Its fields are `clean()`-filtered before the `hiredis_raw` string build, and it writes only to `campaign:events:fs` (FS ACL `+xadd` on that one stream).
- Redis ACL, per-key: the root of every user is `-@all` with no key patterns. FreeSWITCH is limited to `getdel` on intents, `set` on claims and `xadd` on the fs stream. Telephony is read-only on routing keys. The `default` user is off.
- Tenant isolation in the database: RLS FORCE is on for `campaigns`, `dnc_numbers`, `campaign_attempts` and `campaign_contacts` (parent-join policy), and `test_rls_coverage.py` lists the parent-join tables. Platform-conn attempt reads pin `a.tenant_id = $2`.
- Route authorization: campaign and DNC routers depend on `bind_path_tenant` and `require_path_tenant_access`, and mutations require `superadmin|admin`. Capacity routes require superadmin and platform scope. A by-id DNC delete is looked up through RLS first, so a foreign id gets the same 404 as a missing one.
- Kamailio `100[0-2]` is now anchored (`^...$`), so an egress callee containing 1000-1002 is no longer diverted to FS public.
- Carried from round 4, re-read against af99c22 and unchanged: egress token HMAC with single use and expiry, the dial-handler HMAC over raw `$rb`, webhook signature verified before the nonce, and `tenant_id` from the verified account.
