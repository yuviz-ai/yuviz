Both halves can fail, for the right reason.

2. **CLOSED, with two residual weaknesses (new minor 6).** `services/conversation/tests/test_out_responses_tripwire.py` now resolves grep hits to real classes with an AST pass and asserts over that computed list — the previous defect (a mechanical enumeration whose result the assertion ignored) is gone. `CallFlowConversationHandler` is now covered, via `_sets_instance_attr` recognising its `self.out_responses = Queue()`; the `session.py`/`servicer.py` exclusion is necessary (the Protocol body itself is shape-matching and carries no attribute value). 3. **CLOSED — generation counter is sound.** `_listen_generation` starts at 0, is bumped on line 175 as the first statement of `_arm_timer()`, and `_arm_timer()` is the only site that creates a timer task and the only site that bumps — reached from exactly one place, the `Listen` branch of `_run_actions` (`:144`). So every armed timer carries a unique generation, including a replay's (`_invalid_attempt()` returns a fresh `Listen`, which re-enters that same branch), the driver drops any `("timeout", g)` with `g != self._listen_generation` (`:113-115`), generation 0 can never be enqueued, and Python ints do not wrap. The new test (`test_callflow_handler.py:296`) drives the real driver task, and its assertions can fail: without the guard the injected stale timeout is accepted at the replayed `menu`, takes `_menu_timeout_graph`'s explicit `timeout` edge to the promptless `gone` hangup, and both `runner.node.id == "menu"` and `len(responses) == 1 / not end_call` break. The `timeout_ms = 5000` override is load-bearing exactly as the agent describes — at the fixture's 20ms the replay's own real timer matures inside the 50ms sleep and produces a false pass. The adapted distinct-node test (`:269`) reads `handler._listen_generation` and injects an int, so it compares int to int — meaningful, not a vacuous type mismatch.

**No interaction damage.** The three fixes are confined to `pipeline.py` + `test_pipeline.py`, `test_out_responses_tripwire.py`, and `callflow/handler.py` + `test_callflow_handler.py` respectively; no conflict markers anywhere under `services/` or `libs/`, no leftover duplicate of the moved statement (`_interrupt_workflow_background_llm` has exactly its two legitimate call sites, `pipeline.py:791` and `:1172`), and the generation rename left no `node_id`-comparison remnant in the driver.
