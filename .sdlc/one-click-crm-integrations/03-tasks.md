# Tasks: One-click CRM and scheduling integrations (catalogue extension of connector-presets-oauth)

Design: `.sdlc/one-click-crm-integrations/02-design.md`. "Reconciliation table" below means its 21-row table at the top; where a task cites a shipped line number, that table already corrected it, so do not re-derive it. Architecture rule for every task: a CRM connector is an ordinary `custom_apis` row written by a preset and dispatched by `execute_api`; no task adds a parallel path, a second scope map (scopes live only in `presets.PRESETS[...].scopes`), or a tenant-writable surface for `endpoint_base_source`, `oauth_connection_id`, `response_transform`, `value_digits_only` or `value_prefix`.

Ordering principle: schema defaults are inert, then the host-binding control lands before any provider that could use a composed origin exists, then the projection lands before any preset row that applies it, and the providers and preset rows that make the feature reachable come last. If the batch stops after any task, nothing is reachable that is not already guarded (unset-env providers are absent from the catalogue).
