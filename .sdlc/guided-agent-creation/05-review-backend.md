# Code review
VERDICT: AMBER

Scope: backend only (database/, proto/, services/config/, services/conversation/, services/webcall/, libs/config_sdk/), diff `origin/redesign...HEAD`. Checked against 02-design.md Interfaces and Test plan and the approved deviations in approvals.md. The schema, credential redeem, Accept/Undo SQL, slot stripping, conversation test branch, servicer refusal, webcall first-frame gate, turn reservation and revise check order all match the design. The test plan items have corresponding tests. Neither finding is blocking. Both are error paths that give the wrong status code.

1. [minor] A malformed 200 response from the model vendor comes back as a 404 that echoes a Python exception string — `services/config/routers/agents.py:261` and `:290` (root cause: `services/config/system_prompt.py:194`, `:217`) — fails when: Anthropic returns 200 with `content: []`, or OpenAI returns `choices: []`. `resp.json()["content"][0]` raises IndexError, and `["choices"]` on an unexpected body raises KeyError. Both are subclasses of LookupError, so `except LookupError` in `test_chat`/`revise_prompt` returns `404 {"detail": "list index out of range"}` (or `"'choices'"`). Easy treats that as a missing session or config, not as `ai_unavailable`. OpenAI `content: null` raises AttributeError on `.strip()` and gives a 500. — fix: in `_call_openai`/`_call_anthropic`, catch `(KeyError, IndexError, TypeError, AttributeError)` around the response parse and re-raise as `ValueError("unexpected LLM response")`.

2. [minor] A permanent configuration problem is reported as a temporary `502 ai_unavailable` — `services/config/routers/agents.py:263` and `:296` — fails when: a chat-template agent is created through `/from-template` with an LLM config whose engine Conversation supports but `_CALLERS` does not, such as `ollama` (services/conversation/providers/llm/ollama.py), or with one that has no `api_key_ref`. `_load_tenant_llm_config` raises ValueError (`system_prompt.py:235-242`). The routes' blanket `except ValueError` turns that into 502 `ai_unavailable` on every chat turn and every revise, so the user is told to retry something that can never succeed. `/from-template` accepted the config without checking. — fix: raise a distinct exception type (or token) for "engine unsupported / no key" from `_load_tenant_llm_config` and map it to a 4xx such as `422 llm_unsupported`, keeping 502 for transport and vendor failures only.
