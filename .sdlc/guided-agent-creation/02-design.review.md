# Review: guided-agent-creation design
VERDICT: AMBER

1. [blocking] Accept cannot honour criterion 35's exemption for tokens in the user's problem text, because the Accept body carries no `problem`, yet `find_customer_data(proposed, base, problem, caller_lines)` needs it. A fix that revise let through because the user typed the number is then rejected 400 `customer_data` at Accept. — Interfaces: `POST /prompt/accept` body vs `find_customer_data` — fix: add `problem` (<=1000) to `PromptAccept` and pass it to the check, or drop the problem-text exemption from both routes.
2. [blocking] "The slot prompt never leaves the server" is enforced only in `_public_agent` and `_audit_view`, but `update_agent` skips `_audit_view` when `mirrored_graph` is true (`agents.py:377-378`), so raw rows with `prompt_undo_previous` reach `audit_log`. Accept and Undo also mirror graphs and will take the same path. Other `SELECT *`/`RETURNING *` readers and `append_version` are not enumerated (lesson 33). — Changes row for `agents.py` — fix: strip the two slot columns in a single helper that every audit, version and payload path calls. Add a test that no `audit_log` or `agent_versions` row contains the slot text after Accept.
3. [minor] Chat turns insert `turn_number = max+1` with no lock or unique key on `(session_id, turn_number)`, and the 40-turn cap is not specified (how it is counted). Two concurrent `/test-chat` calls get the same number and can both pass the cap. — Data, "Chat test rows" — fix: `SELECT ... FROM calls WHERE session_id=$1 FOR UPDATE` in the turn transaction and derive both the number and the cap from it.
4. [minor] "Active agents with no credential behave exactly as today" is false for webcall. `webcall/__main__.py:276` hardcodes `direction="test"` for every browser session, so an active agent with an incomplete provider set, or a missing DB row, now gets `AGENT_UNAVAILABLE` instead of the legacy fallback. That includes the Advanced test page, which criterion 29 says stays unchanged. The Risks entry mentions only dev workflows. — Decisions 4 and Risks — fix: state that this applies to all webcall sessions, or scope the new refusal to sessions that present a credential or whose agent is inactive.
5. [minor] The LLM config used by `test-chat` is unspecified (revise has a fallback chain, chat does not). The cross-tenant `LookupError` path is therefore untested for chat. — `POST /test-chat` — fix: state "agent's llm_config_id, else tenant default, via `_load_tenant_llm_config`" and add a foreign-id case to Integration 1.
