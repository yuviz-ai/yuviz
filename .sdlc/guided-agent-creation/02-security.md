# Security review: .sdlc/guided-agent-creation/02-design.md (round 2)
VERDICT: GREEN

All four round-1 findings are closed in the design. One new low finding: a test gap on the first-frame control. It does not block.

## Round-1 fixes, verified
- **R1-1 (medium), closed.** Design file table (`agents.py` row): `_validate_provider_assignments` now raises `f"{field} not found"` both for a missing id (today `agents.py:211`) and for a foreign-tenant id (today `agents.py:221`). It still runs one `SELECT ... FOR SHARE` lookup. I traced the code order in `agents.py:201-224`: UUID parse, then lookup, then tenant compare, then role, then voice. So the role-mismatch and unusable-voice errors (`:222-224`) only fire after the tenant compare has passed, which means only for the caller's own rows. The new message has no id interpolation. The UUID-format 400 does not depend on the target. One function serves all three routes: `create_agent` (`:260`) and `update_agent` (`:335`) are its only callers, and from-template goes through `create_agent` (design, Config routes). `system_prompt.py:126` (the same leak in `_load_tenant_llm_config`) is fixed by criterion 47 and the test-chat test at design line 277.
- **R1-2 (low), closed.** The credential leaves the URL. `useWebCall.ts` sends `&test=1` and puts `{"type":"test_credential",...}` as the first frame in `onopen`. Webcall waits at most 5 s, and on a wrong frame or a timeout it closes with 1008 and does not write `session_open`. The credential is minted in a JSON response body and is never in a URL. The Risks section now admits that a credential which is never redeemed stays live for its 60 s TTL. That residual is acceptable, because no log sink sees the credential any more.
- **R1-3 (low), closed.** `{{` and `}}` are rejected in `name`, `business_name` and `business_facts`. Revise and Accept reject a `{{`/`}}` count that rises above the stored base. The runtime round-trip test runs the real `libs/config_sdk/workflow.py:render`. I checked the regexes (`workflow.py:46-47`). `_ANY_BRACES_RE = \{\{[^}]*\}{0,2}` needs a literal `{{` to start a match, and `_TEMPLATE_RE` needs `{{...}}`. So once both tokens are absent, tenant text passes through `render` byte-identical, and single braces stay literal.
- **R1-4 (low), closed.** The chat `calls` row is inserted with `ended_at=now()`, and each turn's reservation update refreshes it. It therefore never matches `agents.py:430`, `live_calls.py:67,117` or the intervention lookup at `live_calls.py:245`. The design includes a test that deletes a chat-tested agent. I checked other effects of a row being born ended. Outside tests, the only readers of `ended_at` are `services/config/{calls,live_calls,agents}.py`, and Conversation's `transcript_builder.py` reconcilers only touch `ended_at IS NULL`. No post-call worker scans `calls`, so no analysis, webhook or sentiment run is set off by a chat row.

## Findings
1. [low] Nothing tests that the first-frame credential is never logged, and the existing webcall reader logs whole frames. `services/webcall/__main__.py:132` logs `"malformed control message=%r"` with the full frame text. The design states "the frame is never logged", but nothing checks it. The webcall unit test (design line 293) asserts only the 1008 close and that no `session_open` was sent. The sentinel-log test (design line 303) covers create, revise, accept and chat, not the voice/webcall path. If the implementer sends a rejected or non-JSON first frame through the existing `_browser_to_grpc` parse-and-log path, or logs it next to the 1008, the credential lands in webcall's logs. The same happens with a version-skewed client that sends the frame without `test=1` and with slightly malformed JSON.
   Attack: someone who reads webcall logs or the log aggregator, but holds no admin JWT, replays a credential that was logged and not yet redeemed. They must do it within 60 s, for example after the Conversation open failed. They get a voice session with the tenant's inactive agent, running on the tenant's STT, LLM and TTS keys. This reopens R1-2 through a different sink.
   Fix: in the webcall unit test, capture logs at DEBUG and assert that a sentinel credential appears in no record. Cover three first frames: a wrong `type`, malformed JSON containing the sentinel, and a binary frame. Also cover a credential frame sent without `test=1`. The first-frame handler must never call the `_browser_to_grpc` parse path.

## Verified controls
- The `test=1` branch adds no new reach. With an empty credential (proto3 `""`), Conversation's `ctx.test_credential` is falsy, so the session takes today's credential-less path. That is the same result as omitting `test=1`. Only a non-empty credential that redeems lifts the inactive check (design lines 232-239).
- Voice redemption is bound to the tenant slug, the agent slug and the resolved `agent.id`. The id check catches an agent deleted and re-created under the same slug. Single use is enforced with GET, then the channel check, then DEL; only the caller whose DEL returns 1 wins, so two racing redeemers cannot both succeed. This replaces `MULTI GET DEL`, which would consume a credential on a channel mismatch. A channel mismatch leaves the key, and a corrupt record returns `None` and is left to expire. The Redis key is the SHA-256 of a `token_urlsafe(32)` token.
- Per-caller invariance on the new routes. Every agent lookup is `id AND tenant_id AND deleted_at IS NULL`, giving `404 "agent not found"`. Foreign, missing and non-UUID provider ids get the identical `404 "provider_config not found"` on test-chat and revise. Chat credential mismatch or expiry gets the same 404 as a missing session.
- `_resolve_tenant` binds the path tenant to the verified token. `require_role("superadmin","admin")` guards every new route, including `GET /agent-templates`.
- Chat turns re-run `get_current_user` and `require_role` on every request (lesson 27). The design states the gap in voice redemption's authority re-check (lesson 16): it is bounded by the 60 s TTL, which is no longer than the identity memo.
- The design's turn reservation is one conditional `UPDATE ... WHERE session_id AND tenant_id AND agent_id AND direction='test' AND turn_count < 40`. It cannot overrun under concurrency, and it now also refreshes `ended_at`.
- Accept and Undo are single conditional updates guarded by the hash precondition. That precondition also makes "stored prompt" equal to the revise base, which is what the Accept brace-count check compares against.
- Single-pass `re.sub` for `{agent_name}`/`{business_name}` in Config, with no rescan of replaced text. Facts are appended, not substituted.
- Servicer logging: `servicer.py:122-143` copies `open_req` fields one by one and logs only the session id and tenant (`:133-134`). `SessionContext.test_credential` is `repr=False`.
- The deviation from PRD criterion 13 is security-neutral to positive. Refusing `{{`/`}}` keeps the PRD's "never evaluated" guarantee and fails closed. Single braces and other template-like text are still stored literally, and the round-trip test proves it. Hardening note, not a finding: the brace check runs on each field separately, so the catalog should never place two tenant fields side by side. Asserting zero `{{`/`}}` on the composed greeting and prompt would make that guarantee structural.
