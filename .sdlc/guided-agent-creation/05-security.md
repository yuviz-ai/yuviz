# Security review: guided-agent-creation (code, `git diff origin/redesign...HEAD`)
VERDICT: GREEN

## Findings
None. I checked every candidate below against a concrete attacker and dropped it when I could not name one:
- Revise and Accept accept any `calls` row with `direction='test'`. Webcall hardcodes `direction="test"` for every browser session (`services/webcall/__main__.py:248`), so a public credential-less webcall session also counts as a "test session". `service_ready` now also hands its `session_id` to unauthenticated callers. Dropped: the transcript stays in-tenant and in-agent (`agent_testing.py` `load_test_transcript`). Using it needs an admin JWT for that tenant. The UI only submits its own session id. And the revise output gives the admin nothing they cannot already write with `PATCH`. No session_id-keyed route accepts it as a capability (`routers/calls.py:86,95` and `routers/live_calls.py:86` all sit behind tenant auth).
- Voice redemption does not re-check that the minting admin still exists or still holds the role (lesson 16). Dropped as a finding because the design accepted it as a residual. The window is the 60 s credential TTL, which is no longer than the `get_current_user` authority memo. Chat turns re-run `require_role` on every request.
- The throttles are per-process in memory (`app.py` `AgentAssistThrottle`). This follows the existing `InviteThrottle` precedent, and the LLM cost lands on the tenant's own keys. No cross-tenant abuse is possible.

## Verified controls
1. Every new route (`from-template`, `test-sessions`, `test-chat`, `prompt/revise`, `prompt/accept`, `prompt/undo`) uses `Depends(require_role("superadmin","admin"))`. FastAPI awaits that dependency, and it chains `get_current_user` (`deps.py:76`). The router-level `bind_path_tenant` + `require_path_tenant_access` apply too, so none of the guards is an un-awaited coroutine.
2. `GET /agent-templates` (`catalog_router`) is authenticated through `require_role`, which depends on `get_current_user`. It returns only static catalog fields (`public_catalog`). No new route can be reached without authentication.
3. `_resolve_tenant` binds the path slug to the verified JWT tenant and returns 404 on a mismatch. Service accounts are unscoped there, but they are `viewer`, so `require_role` rejects them first.
4. `_load_agent` does an explicit `str(agent.tenant_id) != str(tenant.id)` compare and gives a single 404 "agent not found" for foreign, missing and soft-deleted ids. It does not rely on RLS, which is inert under a BYPASSRLS DSN (lesson 36). A non-UUID gets a target-independent 400.
5. Per-caller invariance holds. Test-chat answers 404 "test session not found" for a wrong, expired, foreign-agent or foreign-session credential. Revise and Accept answer 404 "test session not found" for foreign or missing session ids. `_load_tenant_llm_config` answers 404 "provider_config not found" for foreign, missing and non-UUID ids. `_validate_provider_assignments` now answers "{field} not found" for missing and foreign ids alike, and its role and voice errors fire only after the tenant compare.
6. Undo and Accept: `_replace_prompt` locks with `id AND tenant_id AND deleted_at IS NULL`, and the conditional UPDATE repeats `tenant_id`. When nothing matches, `_conflict_or_missing` re-runs `_load_agent`, so a foreign id gets 404 and only the caller's own agent gets 409. Undo never touches another tenant's row.
7. `load_test_transcript` scopes by `session_id AND tenant_id(slug) AND agent_id AND direction='test'`. The chat turn reservation UPDATE carries the same four predicates and `turn_count < 40`, so it cannot overrun under concurrency.
8. Credential minting: `secrets.token_urlsafe(32)`. Redis holds only `testcred:<sha256>`, never the plaintext. The TTL is enforced server-side by Redis `EX`: 60 s for voice, 900 s for chat. Lookup goes by hash, so no timing-sensitive comparison exists.
9. Credential redemption: GET, then the channel check, then DEL. Only the caller whose DEL returns 1 wins, so single use holds under a race. A channel mismatch does not consume the credential. A corrupt record returns None.
10. Voice binding (`conversation/__main__.py` `_resolve_session_deps`): the grant's tenant slug and agent slug must match the session, and the resolved `agent.id` must equal `grant.agent_id`. Any failure raises `AgentUnavailable` with no legacy fallback, and the servicer yields a fatal `AGENT_UNAVAILABLE` without building a session.
11. Chat binding (`run_chat_turn`): the grant's tenant slug, agent id and session id must all match, and the turn also re-runs JWT, role, tenant and agent checks every time.
12. The credential-less fallback is unchanged. `include_inactive=True` is passed only on the credential branch. Without `test=1` or with an empty credential, the code takes the old resolve-then-legacy path byte for byte. With `test=1` and a bad or absent first frame, webcall closes 1008 before opening gRPC. The feature does not widen unauthenticated webcall reach.
13. First-frame transport: `useWebCall.ts` sends only `&test=1` in the URL and puts the credential in `onopen`'s first frame. The client marks the credential spent (`""`) and refuses to reuse it. `_read_test_credential` never logs. The malformed-JSON log at `webcall/__main__.py:87` now logs only type and length, and the unknown-type log prints only `type`. The credential lives only in React state: there is no `localStorage`, `sessionStorage`, router push or URL, so it never reaches browser history.
14. No log or repr sink: `SessionContext.test_credential` is `repr=False`, the servicer logs only the session and tenant (`servicer.py:111`), Config has no body-logging middleware (CORS only), and the OpenAI and Anthropic warning logs no longer include the response text.
15. The channel is server-derived (`_agent_channel` from the stored template). A voice credential cannot be minted for a chat agent, and the reverse is also blocked.
16. The undo slot never leaks. `_public_agent` (which feeds GET, list and the Redis cache `set_json`) strips both slot columns. Every audit write (`create`, `update`, `_replace_prompt`, `soft_delete`) goes through `_strip_slot` or `_audit_view`. `append_version` stores only the mirrored graph. No other module selects `agents.*` into a response (I grepped every `FROM agents` reader).
17. `{{ }}` containment: the schema validators reject `{{`/`}}` in name, business_name and facts. Template `render` substitutes in a single pass with no rescan, and every placeholder is followed by punctuation, so no field adjacency can synthesise `{{`. Revise and Accept reject any rise in the `{{`/`}}` count above the stored base. That matches `workflow.py:37-38`: `_TEMPLATE_RE` and `_ANY_BRACES_RE` both need a literal `{{`.
18. Revise prompt-injection containment: the output is never persisted by revise. Accept re-runs structure enforcement, the brace check and `find_customer_data` server-side against the full transcript, and applies only under the base-hash precondition. That precondition equals the base that was checked, so a proposal cannot be swapped in against a different prompt. Accept grants nothing beyond what the admin's existing `PATCH system_prompt` already allows.
19. Rate caps: per tenant, 20 mints/min, 60 chat turns/min and 20 revises/hour. Each cap is keyed on the resolved tenant id after `_resolve_tenant` and `_load_agent`, so an attacker cannot burn another tenant's counter. There are also 40 turns per session, and `max_tokens` is 300 for chat and 1500 for prompts.
20. Input bounds: `message` and `problem` are ≤1000 characters, `proposed_prompt` is ≤20,000, and transcript input to the model is capped at 30 turns and 8,000 characters. All new SQL is parameterized. The only interpolated pieces, `_PROMPT_SHA_SQL` and the UPDATE templates, are module constants.
