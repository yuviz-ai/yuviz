# Code review (admin-ui)
VERDICT: RED

Scope: `git diff origin/redesign...HEAD -- admin-ui`. Approved deviations in approvals.md were not re-flagged. The Advanced wizard is unchanged: it adds only a mode switch, there are no hooks after the early return, and `?template=` still opens Advanced. Easy error paths render only easyCopy text. The agent page's Undo shows `e.detail`, which matches the existing pattern on that page and is not an Easy surface.

1. [blocking] A second voice test in the same Test step turns Fix on for a session with no transcript, which breaks criterion 33 — `admin-ui/components/EasyTestStep.tsx:66-68` with `admin-ui/lib/useWebCall.ts:184-195` — fails when: the user runs test 1 (transcript has lines, session S1), clicks Stop, then Start talking again. `handleStart` clears `sessionId` but not `transcript`, so on service_ready(S2) `transcript.length > 0` is already true and `onSession(S2)` fires before S2 has a single turn. If the user stops then, or the call ends before anyone speaks, and they go to Fix, "Suggest a fix" sends revise with S2. The server answers 404 "test session not found", and the user sees "This test has ended" where criterion 33 requires "test needed first" with no request sent. The transcript on screen also mixes the two calls. — fix: in VoiceTest, record `transcript.length` when `sessionId` changes and report the session only once the transcript has grown past that mark (or clear the transcript in handleStart).

2. [minor] Going Back from Fix to Test resets the voice session, and leaves a pending proposal with an Accept button that does nothing — `admin-ui/components/EasyTestStep.tsx:66-68`, `admin-ui/components/EasyAgentFlow.tsx:190,453-468,512-513` — fails when: on a voice job the user is on Fix with a proposal shown and clicks Back (it is enabled while `revision !== null`). VoiceTest remounts with an empty hook state, and its mount effect calls `onSession(null)`, which wipes `testSessionId`. Back on Fix, the screen shows "Run a test first" plus the before/after panel with "Accept this fix". `handleAccept` returns early at :190 on `!testSessionId`, so the click does nothing. Even with no proposal, just looking back at Test throws away a fixable session. — fix: do not report null on mount (only report on a session change), and hide Back on Fix while a proposal is pending.

3. [minor] The voice "Start talking" button stays enabled while the credential is minted, so a double click opens two calls — `admin-ui/components/EasyTestStep.tsx:70-79,88-91` — fails when: the user double-clicks Start, which only becomes Stop once the hook reaches "connecting", after the mint returns. Both clicks mint, the effect fires `start()` once per credential, and the hook's `handleStart` (useWebCall.ts:184) overwrites `wsRef`/`streamRef` without tearing down the first call. The first WebSocket and microphone stay open with nothing tracking them, and its transcript lines interleave with the second call's. — fix: add a `minting` flag and disable Start while it is set.

4. [minor] Easy error messages are not announced to assistive tech — `admin-ui/components/EasyAgentFlow.tsx:368,406,481,506`, `admin-ui/components/EasyTestStep.tsx:99,185` — fails when: a screen-reader user presses Continue on step 2 with the name empty. `fieldError` renders in a plain `div.error-banner` while focus stays on the button, so nothing is read out and the step looks unresponsive. The success note at :480 does have `role="status"`, so the asymmetry is unintended. — fix: add `role="alert"` to the Easy error banners.
