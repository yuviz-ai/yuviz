[minor] Q1 and the "Bypass sites" table both assert `tenants` is fully out of RLS scope ("`tenants` is out of RLS scope, but NULL-tenant reads still need a connection that resolves"), yet `tenant_conn()`'s own one-statement GUC resolver runs `SELECT ... FROM tenants t WHERE ...` on every request-scoped connection before RLS policies are even evaluated — this is correct and intentional per the design, but the design never states which role/grant permits `yuviz_app` to read `tenants` given `GRANT SELECT ... ON ALL TABLES` predates `tenants` being carved out; since `tenants` has no policy and is not `FORCE`d, this happens to work today only because RLS was never enabled on it — worth one sentence in the Data section stating explicitly that `tenants` gets ordinary GRANTs but no `ENABLE ROW LEVEL SECURITY`, so a future contributor doesn't "complete" the enumeration by adding a policy to it and break every `tenant_conn()` resolution.
