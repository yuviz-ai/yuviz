# Design: Transcript and turn-count accuracy

## Approach
Every fix lands at the point where the wrong value is first produced, inside the existing per-session write chain (`TranscriptBuilder._spawn`), so write ordering and tenant guards stay as they are. Two facts that have no home today get a column on `calls`: the post-transfer summary (`calls.session_summary`) and the agent that took over after an IVR handoff (`calls.answering_agent_id`). The summary therefore stops being a fake turn, and the original `agent_id` keeps its meaning. A flow-only call's clean ending is recorded through the existing `record_workflow_outcome(disposition=...)` path, and the dashboard reads it. This avoids a new close_reason vocabulary, which every close_reason consumer (export, outcome labels, agent stats) would then have to learn. Reconcile sweeps derive `turn_count` from `transcript_entries` in the same UPDATE, because the in-memory counter died with the process.

## Data
Append next to `ALTER TABLE calls ADD COLUMN IF NOT EXISTS detected_languages` in `database/schema.sql`. All statements are additive and idempotent, with no destructive DDL and no backfill, so lessons 5/10/13 have nothing to guard.
```sql
-- Post-transfer handoff summary; never a transcript turn (session_finalizer.PersistSummaryStep).
ALTER TABLE calls ADD COLUMN IF NOT EXISTS session_summary TEXT;
-- Agent that took the call after a call-flow handoff; agent_id keeps the flow/IVR agent. NULL = no handoff.
ALTER TABLE calls ADD COLUMN IF NOT EXISTS answering_agent_id UUID REFERENCES agents(id);
CREATE INDEX IF NOT EXISTS idx_calls_answering_agent ON calls(answering_agent_id) WHERE answering_agent_id IS NOT NULL;
```
The readers (`get_call` uses `c.*`, the admin page) ship in the same PR as the writers (lesson 11).

## Interfaces
- `TranscriptBuilder.record_turn(self, session_id: str, caller_text: str, caller_confidence: float, ai_response: str, interrupted: bool, latency: TurnLatency | None = None, *, tool_calls: list[dict[str, str]] | None = None, count_barge_in: bool | None = None) -> None`. `count_barge_in=None` means "same as `interrupted`". `tool_calls` is written as `$15::jsonb`, or NULL when empty (AC20). Only the keys `name` and `status` are serialized; arguments, results and `error` are never passed (AC21).
- `TranscriptBuilder.record_summary(self, session_id: str, summary: str) -> None`: spawned on the session chain, `UPDATE calls SET session_summary = $2 WHERE session_id = $1 AND tenant_id = $3` under `tenant_conn(..., reason="conversation-session-write")`, same shape as `_record_detected_languages`. Text goes through `_strip_nul`.
- `_begin_call` conflict clause: `ON CONFLICT (session_id) DO UPDATE SET answering_agent_id = CASE WHEN EXCLUDED.agent_id IS DISTINCT FROM calls.agent_id THEN EXCLUDED.agent_id ELSE calls.answering_agent_id END WHERE calls.tenant_id = EXCLUDED.tenant_id RETURNING 1`. The tenant guard is unchanged. The only repeat `begin_call` for a live session is the delegate handoff (comment at transcript_builder.py:185, callflow/handler.py:69).
- `_strip_nul(text: str | None) -> str | None`: `text.replace("\x00", "")`. It is applied in `record_turn` before the turn number is assigned, so the insert cannot fail on NUL and leave a gap. The same treatment covers tool names, because jsonb rejects `\u0000` too.
- `ToolCallFinishedEvent(tool_name: str, status: str)` in `tools/llm_adapter.py`. `status` is `ToolStatus.value`.
- `_llm_to_tts(...) -> AsyncGenerator[tuple[str, bytes, bool, str], None]`. The 4th element is defined once, in Changes row `pipeline.py`(a).
- Dashboard predicate in `get_dashboard_stats`, with `flow_clean := COALESCE(close_reason = 'TRANSFER_SUCCESS' OR (disposition = ANY($3) AND close_reason = ANY($4)), FALSE)`, `$3 = list(_FLOW_CLEAN_DISPOSITIONS)` and `$4 = list(_OUTCOME_REASONS["done"])`:
  - success: `ended_at IS NOT NULL AND close_reason IS DISTINCT FROM 'TRANSFER_FAILED' AND (turn_count > 0 OR flow_clean)`
  - failed: `ended_at IS NOT NULL AND ((turn_count = 0 AND NOT flow_clean) OR close_reason = 'TRANSFER_FAILED')`
  - The window predicate, the `tenant_conn` connection and `WHERE tenant_id = $1` stay as they are today (calls.py:151-172).
- `GET` call detail response (served by `get_call`) gains `session_summary`, `answering_agent_id` and `answering_agent_name`. The transcript endpoint is unchanged.

## Risks
- Producer–consumer skew could still overstate the spoken text. Mitigation: `spoken_piece` is appended in the consumer, and only after that chunk's `HandlerResponse` is yielded, so pieces still queued (`_TURN_QUEUE_MAX`) or never synthesized are excluded. Text is accurate to the sentence: a sentence whose audio was sent but cut mid-play is stored whole, which AC7 allows ("sentences or portion").
- `_llm_to_tts`'s tuple shape overlaps with fix/tts-failure-handling. Mitigation: only the yield sites gain a 4th element and both consumers (`_run_turn`, `on_transfer_failed`) are updated. The overlap is listed in the PR body as the constraint requires.
- NULL `disposition` would make `NOT flow_clean` NULL and silently drop the call from `failed_count`. Mitigation: `flow_clean` is wrapped in `COALESCE(..., FALSE)`, and test case 1 below covers it.
- The disposition strings are written by conversation (`callflow:` + `Hangup.reason` from callflow/runner.py:173/201/233) and read by config, so they could drift. Mitigation: a config test asserts `_FLOW_CLEAN_DISPOSITIONS` equals `"callflow:" +` each clean reason literal found in `callflow/runner.py` (`flow_complete`, `retries_exhausted`). The test also asserts that the set of reasons it found has size 4, so a new Hangup reason trips it (lesson 12).
- `record_workflow_outcome` also writes `nodes_visited='[]'` and `extracted_variables='{}'` on flow-only calls. Mitigation: those fields are unset on flow-only calls today. A handoff call never reaches the flow Hangup branch, because the driver loop exits once `_delegate` is set (handler.py:87).
- The answering-agent value could come from another tenant (lesson 48). Mitigation: it is the delegate pipeline's own `self._agent_id`, resolved server-side through `agent_slugs`, which `CallFlowHandler` builds from the tenant's own visible agents. The upsert keeps `WHERE calls.tenant_id = EXCLUDED.tenant_id`. The `aa` join follows the existing unscoped `agents a` join in `get_call`. A composite tenant FK is not possible because `calls.tenant_id` is a slug.
- Keeping the user message after a whole-reply TTS failure leaves two consecutive `user` messages in history. Mitigation: OpenAI and Ollama accept this. The Anthropic Messages API merges consecutive same-role turns, and Gemini accepts them. A test runs the history through `providers/llm/anthropic.py` and `gemini.py` message builders to prove neither raises.
- Reconcile `turn_count` from `COUNT(*)` could count a legacy `[session_summary]` row on a call left open across the deploy. Mitigation: the window is a single deploy; historical backfill is out of scope per the PRD.
- Deriving `turn_count` adds a correlated subquery to the reconcile UPDATE. Mitigation: it is served by `idx_transcript_entries_session` and only touches rows with `ended_at IS NULL` for one node or a dead node. The node scoping predicates are unchanged (AC13).
- Recording the recovery turn immediately inside `on_transfer_failed` could race the failed turn's own row. Mitigation: both writes go through the same `_spawn` chain, and the requesting turn's `record_turn` (pipeline.py ~1187) runs before the transfer request is yielded, so turn_number and `created_at` order follow call order.
- `ToolCallFinishedEvent` is a new event on `run_turn`. Mitigation: `_token_stream` (pipeline.py ~1611) is its only consumer and swallows it (`continue`) before `_with_filler_timer`. Any other `run_turn(` caller found by grep must ignore it, and the test suite catches a consumer that asserts on event types.

## Test plan
Unit tests (asyncpg pool mocked as in the existing `test_transcript_builder.py`; config SQL tests in `services/config/tests/test_calls.py` against the test DB where that file already does). Every case must fail on base and use shipped constants (AC22).
1. Dashboard (AC1-4): seed one ended call each for: turn 0 + `callflow:flow_complete` + `stream_ended`; turn 0 + `TRANSFER_SUCCESS`; turn 0 + `TRANSFER_FAILED`; turn 0 + `reconciled_stale` + NULL disposition; turn 0 + `caller_hangup` + NULL disposition; one live call. Assert exactly `success_count = 2` and `failed_count = 3`, and that the live call is in neither. On base this gives 0/5, so the test fails.
2. Transcript integrity: `PersistSummaryStep` produces no `record_turn` call and one `record_summary` call. `get_call` returns `session_summary` while the transcript has no `[session_summary]` row (AC5/5a). `record_turn` with `"a\x00b"` produces SQL args with no NUL and the next turn_number is contiguous (AC9). `on_transfer_failed` records its row before a later turn's row, not at `on_session_end` (AC6).
3. Spoken text (AC7/8): a scripted LLM yields sentence 1, then sentence 2 tokens; cancel is set after sentence 1's audio is consumed. The stored `ai_response` equals sentence 1 exactly. A fully played reply stores the full text with `interrupted=False`. Whole-reply TTS failure keeps the caller's message in `history` and in the transcript (AC17).
4. Counters: the hang-up path (`aclose` mid-turn) leaves `barge_in_count` 0, and a real barge-in gives 1 (AC14). `reconcile_stale_calls`, `reconcile_dead_nodes` and `reconcile_inactive_calls` SQL each contain the `transcript_entries` count subquery and keep their node predicates. A DB-backed test with 3 rows / 0 rows gives `turn_count` 3 / 0, and another node's live call is untouched (AC10-13).
5. Attribution, stage and tools: a second `begin_call` with a different agent sets `answering_agent_id`, while a single `begin_call` leaves it NULL. `get_agent_call_stats` and `list_calls(agent_id=sales)` include the handed-off call (AC15/16). `CallFlowHandler` with no delegate writes `waiting_for_human` then `human_connected` (AC18). An interrupted turn after `pay_order` stores `tool_calls == [{"name": "pay_order", "status": "success"}]`, and a serialization check asserts that no argument value (card or PIN fixture) appears in the stored JSON (AC19-21).
Regression: `pytest -q services/conversation/tests services/config/tests`, with failures diffed against base (AC23).
